`@vessel-dsp/runtime` executes a `@vessel-dsp/compiler` program on audio streams. It builds the MNA matrices at `prepare()` from the program's stamp operators, then solves per sample with trapezoidal integration and damped Newton Raphson iteration. It is headless TypeScript with no audio backend; the host drives it block by block. The same programs also run on the compiled C++/WASM console that ships in this package (see the WASM console below).

## Install

`@vessel-dsp/runtime` 0.3.0 is on npm, with `@vessel-dsp/compiler` 0.2.0 alongside it. Use runtime 0.2.1 or later: 0.2.0 cannot load a program inside an AudioWorklet (`structuredClone` is not defined there).


```bash
bun add @vessel-dsp/runtime @vessel-dsp/compiler
```

The package publishes `.` (the `ReferenceRuntime` console, chain runtime, admission, settling, and measurement helpers) and `./wasm/*` (the compiled solver console: `v2_dsp.cjs` glue plus `v2_dsp.wasm`). Known-answer circuits for probes live in the compiler's `./fixtures` subpath. Every sample below runs against these published entry points; the fixtures import from `@vessel-dsp/compiler/fixtures` and compile with the dependency-free `emptyRegistry`.

## Construct and prepare

The constructor takes the program and optional block elimination only. The sample rate goes to `prepare()`, which has no default. `process()` takes a `Float64Array` and returns a new `Float64Array`.

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";
import { ReferenceRuntime } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const runtime = new ReferenceRuntime(compiled.program);
runtime.prepare(44100);
const output = runtime.process(new Float64Array(128));
console.log("length:", output.length);
console.log("is Float64Array:", output instanceof Float64Array);
```

```text
length: 128
is Float64Array: true
```

Every `prepare()` option, with what it does:

- `maxNewtonIterations`: CPU versus accuracy knob. Samples that exhaust it are held and counted in telemetry, never silently interpolated.
- `realtimeBudget`: opt in admission gate. Omitted means no gating.
- `inputSourceOhms` (default 0): series impedance driving the input jack. A console setting, not a program one.
- `oversample` (default 1): integer sub samples per host sample. Zero order hold output; no band limiting decimator is implemented.

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";
import { ReferenceRuntime } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const runtime = new ReferenceRuntime(compiled.program);
runtime.prepare(48000, { maxNewtonIterations: 64, inputSourceOhms: 0, oversample: 1 });
const input = new Float64Array(128);
for (let i = 0; i < input.length; i++) {
  input[i] = 0.3 * Math.sin((2 * Math.PI * 440 * i) / 48000);
}
const output = runtime.process(input);
let peak = 0;
for (const v of output) peak = Math.max(peak, Math.abs(v));
console.log("peak:", peak.toFixed(4));
console.log("samples:", runtime.telemetry().samples);
```

```text
peak: 1.3502
samples: 128
```

At `oversample: 2` the same drive renders at peak 1.3501: more solver work per host sample for the same circuit, with no band limiting decimator either way.

## SetControl and positions

`setControl(id, position)` takes 0..1 and applies the program's own taper. Moving a knob re stamps conductances; it never re lowers. The pot-divider fixture declares one control, `Level`:

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { potDivider } from "@vessel-dsp/compiler/fixtures";
import { ReferenceRuntime } from "@vessel-dsp/runtime";

const compiled = compile(potDivider, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const runtime = new ReferenceRuntime(compiled.program);
runtime.prepare(48000);
runtime.setControl("Level", 0.8);
const input = new Float64Array(128);
for (let i = 0; i < input.length; i++) {
  input[i] = 0.3 * Math.sin((2 * Math.PI * 440 * i) / 48000);
}
let peak = 0;
for (const v of runtime.process(input)) peak = Math.max(peak, Math.abs(v));
console.log("level 0.8 peak:", peak.toFixed(4));
```

```text
level 0.8 peak: 0.2400
```

At the default 0.5 the same input peaks at 0.1500: the position is a fraction of the track, not volts or ohms, and the taper curve turns it into a fraction of the parameter range. Call `setControl` between `process()` calls, never concurrently with one.

## Process

`process(input)` renders one block of any length and returns a fresh array. State carries across calls: capacitors, inductor currents, and op-amp pole memory persist, which is what makes a second block a continuation and not a restart.

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";
import { ReferenceRuntime } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const runtime = new ReferenceRuntime(compiled.program);
runtime.prepare(48000);
const first = runtime.process(new Float64Array(128));
const second = runtime.process(new Float64Array(128));
console.log("first[0]:", first[0].toFixed(6));
console.log("second[0]:", second[0].toFixed(6));
console.log("telemetry samples:", runtime.telemetry().samples);
```

```text
first[0]: 0.000010
second[0]: 0.000009
telemetry samples: 256
```

`reset()` clears reactive state. `telemetry()` reports the solver census, including `nonConvergedSamples`, `peakIterations`, `operatingPointSupplyAmps`, and `renderedSupplyPeakAmps` (null until a sample renders).

## Supply control

`getSupplies()` lists every addressable `dc-source` stamp. `setSupply` exists on both consoles — `ReferenceRuntime` and the `V2WasmEngine` below — with the same validation and `RuntimeError` behaviour, and both read back through `getSupplies`. The compiler's `resolveSupplyStamps` (see the Compiler guide) decides which stamps are the external supply; the consoles only retarget the addresses they are given.

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";
import { ReferenceRuntime } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const runtime = new ReferenceRuntime(compiled.program);
runtime.prepare(48000);
console.log("supplies:", JSON.stringify(runtime.getSupplies()));
console.log("rebuilds before:", runtime.supplyRebuilds);
runtime.setSupply(runtime.getSupplies().map((s) => s.address), 9, 30);
console.log("rebuilds after change:", runtime.supplyRebuilds);
runtime.setSupply(runtime.getSupplies().map((s) => s.address), 9, 30);
console.log("rebuilds after same value:", runtime.supplyRebuilds);
```

```text
supplies: [{"address":{"blockIndex":0,"sourceIndex":0},"positive":5,"negative":0,"volts":9,"sourceOhms":1}]
rebuilds before: 0
rebuilds after change: 1
rebuilds after same value: 1
```

What it does and does not do:

- It never mutates the caller `Program`. The touched stamps are replaced on the runtime's own copies, so two runtimes from one program never interact, and a frozen program never throws. After the calls above, the caller program still reads 9 V and 1 ohm.
- The operating point is not re solved mid stream. Reactive state carries over, which is the honest response to hot swapping a battery.
- Call `setSupply` before `prepare()` or mid-stream. The two consoles solve the operating point at different moments — the TypeScript console in `prepare()`, the WASM console lazily on first process — so a call between `prepare()` and the first sample is not guaranteed to agree across consoles. The cross-console test pins the two supported orders on a sagged synthetic stage, agreeing to within 1e-4.

The eight closed refusal reasons for the document-to-stamp join, and the full sag design with its corpus measurements, are in the Compiler guide and the [runtime supply-control design note](https://github.com/vessel-dsp/core/blob/main/docs/design/runtime-supply-control.md).

## WASM console

The compiled solver console (`v2_dsp.cjs` glue plus `v2_dsp.wasm`) ships inside this package under `dist/wasm/`. It is a release artifact, not source: `bun run --cwd packages/runtime build:wasm` (needs `em++`) writes it to the gitignored `src/wasm/`, `build` copies it to `dist/wasm/`, and `prepack` does both, so the tarball always carries a freshly built console. The published tarball is about 1.0 MB packed (3.1 MB unpacked), of which the wasm is 2.1 MB and the glue about 15 KB.

`V2WasmEngine.create()` loads the glue from the package's own `dist/wasm/` — no path to configure. `prepare()` takes an options object (`sampleRate` defaults to 48000); audio moves through `processBlock` on `Float32Array`s, and `destroy()` releases the engine handle:

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";
import { ReferenceRuntime, V2WasmEngine } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const input = new Float64Array(128);
for (let i = 0; i < input.length; i++) {
  input[i] = 0.3 * Math.sin((2 * Math.PI * 440 * i) / 48000);
}
const tsRuntime = new ReferenceRuntime(compiled.program);
tsRuntime.prepare(48000);
const tsResult = tsRuntime.process(input);
console.log("ts peak:", Math.max(...Array.from(tsResult, Math.abs)).toFixed(4));

const wasm = await V2WasmEngine.create(compiled.program);
wasm.prepare({ sampleRate: 48000 });
const f32in = Float32Array.from(input);
const f32out = new Float32Array(128);
wasm.processBlock(f32in, f32out);
console.log("wasm peak:", Math.max(...Array.from(f32out, Math.abs)).toFixed(4));
let maxDelta = 0;
for (let i = 0; i < f32out.length; i++) {
  maxDelta = Math.max(maxDelta, Math.abs((tsResult[i] ?? 0) - (f32out[i] ?? 0)));
}
console.log("max |ts-wasm| delta:", maxDelta.toExponential(2));
wasm.destroy();
```

```text
ts peak: 1.3502
wasm peak: 1.3502
max |ts-wasm| delta: 1.01e-7
```

On this stage the two consoles agree sample by sample to about 1e-7. `getSupplies`/`setSupply` on the WASM console behave as above: after `setSupply(addresses, 9, 30)` its `getSupplies()` reads back 9 V and 30 ohm, tracking exactly the calls the engine accepted.

A host that cannot dynamically import the glue — an `AudioWorkletGlobalScope` bundles it statically and has no `fetch` — passes an already-instantiated module as the second argument to `create()`. The bytes come from the published files, so pre-fetch them from the installed package and hand them to the glue factory:

```ts
import { readFileSync } from "node:fs";
import { createRequire } from "node:module";
import { V2WasmEngine } from "@vessel-dsp/runtime";
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const require = createRequire(import.meta.url);
const gluePath = require.resolve("@vessel-dsp/runtime/wasm/v2_dsp.cjs");
const createModule = (await import("@vessel-dsp/runtime/wasm/v2_dsp.cjs")).default;
const mod = await createModule({ wasmBinary: readFileSync(gluePath.replace(/\.cjs$/, ".wasm")) });

const wasm = await V2WasmEngine.create(compiled.program, mod);
wasm.prepare({ sampleRate: 48000 });
wasm.destroy();
```

## Admission

`admissionVerdict(chain, sampleRate, budget)` asks whether an ordered list of programs fits inside a host CPU budget. Costs add across slots. A single program is a one element chain.

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";
import { admissionVerdict } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

console.log(JSON.stringify(admissionVerdict([compiled.program], 48000, {
  nsPerSolve: () => 1,
  nsPerMacroSample: () => 0,
})));
```

```text
{"fits":true}
```

A budget that prices every solve at 1e12 ns refuses by name with the worst offender:

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier } from "@vessel-dsp/compiler/fixtures";
import { admissionVerdict } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const verdict = admissionVerdict([compiled.program], 48000, {
  nsPerSolve: () => 1e12,
  nsPerMacroSample: () => 0,
});
console.log(verdict.fits ? "fits" : verdict.reason.slice(0, 220));
```

```text
chain of 1 program(s) cannot be shown to fit inside 20833 ns/sample at 48000 Hz (cpuBudgetFraction=1): worst case is 64000000000000 ns/sample across 1 costed block(s), worst offender slot 0 block "analog:0" (9 unknowns,
```

`budgetedIterationsPerSample` (default 64) is a sustained policy allowance, not the solver cap. `predictedWorstCaseNs` returns the same sum as a number for harnesses. `calibrateNsPerSolve` measures this host's real per-solve cost to feed the budget instead of a guess.

## Settling and measurement

`settledRender` renders a program until its output level stops moving, so startup transients are not measured as the circuit. It returns a verdict — `settled` with `rms`, `peak`, and the rendered tail, or a refusal/diverged shape — never a bare number:

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier, resistorDivider } from "@vessel-dsp/compiler/fixtures";
import { settledRender } from "@vessel-dsp/runtime";

for (const [name, source] of [["divider", resistorDivider], ["ce", commonEmitterAmplifier]] as const) {
  const compiled = compile(source, { registry: emptyRegistry });
  if (compiled.status !== "ok") throw new Error("compile failed");
  const render = settledRender(compiled.program, { sampleRate: 48000, hz: name === "divider" ? 1000 : 440, drive: name === "divider" ? 1 : 0.3 });
  if (render.status === "settled") {
    console.log(`${name}: rms ${render.rms.toFixed(4)} peak ${render.peak.toFixed(4)}`);
  } else {
    console.log(`${name}: ${render.status}`);
  }
}
```

```text
divider: rms 0.3536 peak 0.5000
ce: rms 0.9520 peak 1.3498
```

The divider at 1 V drive settles to exactly its 0.5 ratio (rms 0.5 / sqrt(2)). Alongside it the package exports `measureSharedWindow` and `measureInputAttributable` (shared-window comparisons), `settledSweepVerified` (a control sweep with one point verified against an independent render), and `SETTLE_DEFAULTS` (the corpus measured defaults: 0.5 s window, 2 consecutive, 0.25 dB).

## Chain runtime and advisories

`ChainRuntime` runs ordered slots where each slot output feeds the next. `programSlot` wraps a compiled circuit; `processorSlot` wraps a host supplied processor (NAM, IR). `slotContract` exposes what the seam arithmetic needs, and `chainAdvisories` takes those contracts — not the slots — and reports each seam where one side states no full scale:

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { rcLowPass } from "@vessel-dsp/compiler/fixtures";
import { ChainRuntime, chainAdvisories, programSlot, slotContract } from "@vessel-dsp/runtime";

const compiled = compile(rcLowPass, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const chain = new ChainRuntime([programSlot(compiled.program), programSlot(compiled.program)]);
chain.prepare(48000);
const input = new Float64Array(128);
input[0] = 1;
console.log("length:", chain.process(input).length);
console.log("slots:", chain.telemetry().map((t) => t.slot).join(","));
console.log("advisory:", chainAdvisories([slotContract(programSlot(compiled.program)), slotContract(programSlot(compiled.program))])[0]?.code);
```

```text
length: 128
slots: 0,1
advisory: unscalable-seam
```

The fixture states no supply to derive a bound from, so the seam crosses unscaled and the advisory says exactly that. Advisories are carried alongside a successful load, never thrown. `supplyGroundConflicts` names slot pairs that cannot share one supply:

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier, rcLowPass } from "@vessel-dsp/compiler/fixtures";
import { supplyGroundConflicts } from "@vessel-dsp/runtime";

const ce = compile(commonEmitterAmplifier, { registry: emptyRegistry });
const rc = compile(rcLowPass, { registry: emptyRegistry });
if (ce.status !== "ok" || rc.status !== "ok") throw new Error("compile failed");
console.log("two negative-ground stages:", JSON.stringify(supplyGroundConflicts([ce.program, ce.program])));
console.log("ce supplyReference:", ce.program.supplyReference, "/ rc supplyReference:", rc.program.supplyReference);
```

```text
two negative-ground stages: []
ce supplyReference: negative-ground / rc supplyReference: unpowered
```

It fires only when a `positive-ground` program meets a program carrying a positive rail (`negative-ground` or `dual-rail`); `unpowered` programs conflict with nothing. The chain renders correctly regardless — each program is solved against its own rails — because the warning is about the board that would be needed to hear it, not the simulation.

Level helpers at the seam: `seamScale` applies the ratio of adjacent full scales (1 here, since neither side states one), `dacScaleFactor` normalises the last slot for the DAC, and `outputDbfs` reports dBFS after that scale. `outputDbfs(1, 9)` is -19.084850188786497, and the conversion full scale is the declared 1 V reference.

## Error behaviour

Misuse throws `RuntimeError` with a message that names the problem:

```ts
import { compile, emptyRegistry } from "@vessel-dsp/compiler";
import { commonEmitterAmplifier, potDivider } from "@vessel-dsp/compiler/fixtures";
import { ReferenceRuntime } from "@vessel-dsp/runtime";

const compiled = compile(commonEmitterAmplifier, { registry: emptyRegistry });
if (compiled.status !== "ok") throw new Error("compile failed");

const runtime = new ReferenceRuntime(compiled.program);
try {
  runtime.process(new Float64Array(8));
} catch (e) {
  console.log("no prepare:", (e as Error).message);
}
try {
  runtime.prepare(5);
} catch (e) {
  console.log("bad rate:", (e as Error).message);
}
const withControl = compile(potDivider, { registry: emptyRegistry });
if (withControl.status !== "ok") throw new Error("compile failed");
const knob = new ReferenceRuntime(withControl.program);
knob.prepare(48000);
try {
  knob.setControl("NOPE" as never, 0.5);
} catch (e) {
  console.log("bad control:", (e as Error).message);
}
try {
  knob.setControl(withControl.program.controls[0].id, 2);
} catch (e) {
  console.log("bad position:", (e as Error).message);
}
try {
  runtime.setSupply([{ blockIndex: 99, sourceIndex: 0 }], 9, 1);
} catch (e) {
  console.log("bad supply:", (e as Error).message);
}
try {
  runtime.setSupply(runtime.getSupplies().map((s) => s.address), Number.NaN, 1);
} catch (e) {
  console.log("bad volts:", (e as Error).message);
}
try {
  runtime.setSupply(runtime.getSupplies().map((s) => s.address), 9, -1);
} catch (e) {
  console.log("bad supply ohms:", (e as Error).message);
}
```

```text
no prepare: prepare(sampleRate) was never called
bad rate: sample rate 5 is not usable; a program has no default rate
bad control: program has no control "NOPE"
bad position: control position 2 is outside 0..1
bad supply: setSupply: unknown block index 99
bad volts: supply volts NaN is not finite
bad supply ohms: supply sourceOhms -1 is not a finite non-negative resistance
```

`prepare()` also refuses programs needing operators or DSP models it does not implement, naming each missing one, and refuses chains that fail the opt in admission gate.

## Limits

- Oversampling is zero order hold with no band limiting decimator.
- Admission needs host measured costs; without a budget there is no gate, and without a price for a DSP model the chain is refused by model name.
- Op-amp stages draw almost no supply current in the model, so sag on op-amp heavy pedals is under reported. A hard clipper can push current back into the rail, which a real cell cannot absorb.
