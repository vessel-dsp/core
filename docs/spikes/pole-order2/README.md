# pole-order2 scratch harness (2026-10-10)

Scratch harness for `docs/spikes/2026-10-10-pole-order2.md`. **Nothing here ships.** Every script runs from a repository root and measures that tree (the root `tsconfig` maps
`@vessel-dsp/*` to `src`, and the WASM console loads `packages/runtime/src/wasm`), so the same script measures unchanged main in a clone and this worktree. `sync-to-base.sh <tree>` copies the
harness and the stage fixture into another tree. The corpus and study packets are read-only (`~/projects/VesselDSP/{artifacts,workbench}`).

TS = `ReferenceRuntime`, WASM = `V2WasmEngine` (the shipping console).

## Pre-registered closed forms and census (no engine code)
- `closed-forms.ts` -- the discrete non-inverting closed loop of every candidate (BE, trapezoid, first-order-hold, BDF2) against the continuous single pole; closed-loop poles.
- `catalog-poles.ts` -- every railed op-amp stamp's A0, the pole it puts at `GBP / A0`, and its margin to Nyquist.

## Known answer and controls
- `analytic-stage.ts` -- the non-inverting stage on both consoles, os1/2/4/8, measured minus the continuous closed form and minus the named scheme's discrete form; `slope.ts` -- the log-log order of accuracy
  and the os4 bar; `ring-probe.ts` -- step response (the Nyquist ring); `nyquist-ring.ts` / `nyquist-compare.py` -- spectral top bin and band, with the follower impulse as the known-positive;
  `boundary.ts` -- continuity across `poleHz = fs/2`.
- `break-controls.sh` -- the check goes red on one console only (scratch copy).
- `dc-points.ts` -- DC operating points of every document, hashed; `corpus-hash.ts` / `corpus-hash-compare.py` -- render hashes of the documents; `baseline-render.ts` -- the study packets' hashes.
- `parity-os.ts`, `decision-parity.ts` -- TS-versus-WASM parity and the predictor decision counters.

## Cost, stability, movement
- `iterations.ts`, `real-input.ts` / `real-input-compare.py` (guitar DI takes from the workbench's test assets), `cost-ab.ts` (needs an idle box), `canaries.ts`, `mt2-timeline.ts`,
  `stall-hunt.ts`, `stall-diagnose.ts`, `stall-scan.ts` / `stall-scan-compare.py` (every railed document, WASM, stall guard), `bluebox-detail.ts`, `echo-dump.ts` / `echo-trace.ts` (the S5 (iii) fixture),
  `movement.ts` / `movement-compare.py`, `follower-stability.ts` (as the GBW worker left it; needs a typed GBP, which this tree does not read).

## ngspice and the hardware consequence
- `ngspice/` -- `program-to-spice.ts` and `wav.ts`, **verbatim copies** of `workbench/scripts/lib/` (the deck's pole is the continuous one); `ngspice-deck.ts`, `sweep.ts`, `ng-table.py`.
- `three-way-engine.ts`, `three-way-analyse.py`, `hw-merge.py`, `hw-table.py`, `hw-collect.sh` -- the engine columns of the three specimen tables through a tree, and the study's own `pool.py` on them
  (the study's `pool.py` is copied by `hw-merge.py` at run time, unmodified).
- `rate-scan.ts`, `rate-scan-analyse.py` -- the GBW worker's scratch rate scan, kept for reference; not used.

## Candidate and theta arms (scratch, never in the diff)
- `cand-patch.py` -- the TS scheme switch in a scratch clone: `POLE_SCHEME=be|tr|foh|bdf2|theta`, `POLE_THETA`, `GBW_HZ`; `be` reproduces main bit for bit.
- `bdf2-arm.patch` (generated by `make-bdf2-patch.py`) -- **the BDF2 arm as a clean unified diff against the worktree's trapezoid, TS console only.** `cd <tree> && patch -p1 < docs/spikes/pole-order2/bdf2-arm.patch`.
- `bdf2-cpp-patch.py` -- the BDF2 arm for the C++ console (scratch copy of `src/cpp`); `theta-cpp-patch.py` + `build-theta-wasm.sh` -- the theta family for the C++ console (`-DPOLE_THETA=`).
- `theta-map.ts` -- the pre-registered theta map (known answer + convergence), TS or `--wasm-dir=`.
- `export-programs.ts` -- the 145 programs for `generate-kernels.ts`.

`logs/` holds the run logs the note quotes.
